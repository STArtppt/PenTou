# PenTou 笔头

> **本地优先的 AI 对话管理器**
> 把散落在各平台的 AI 对话，沉淀为可检索、可加工、可流转的本地知识资产。

---

## 一、为什么是 PenTou

如果你日常在 ChatGPT、Claude、DeepSeek、Gemini、Cursor、Copilot、Codex、Claude CLI 之间频繁切换，会很快意识到三个痛点：

1. **对话散落**：每个平台一套历史记录，账号注销、服务下线、平台改版都可能让一段灵感悄无声息地丢失。
2. **难以再加工**：平台原生 UI 是给"聊天"设计的，不是给"知识管理"设计的——没有文件夹、没有跨平台搜索、没法对一段长对话做摘要或重写。
3. **数据不归你**：所谓的"历史记录"放在云上，导不出、改不动、搜不到。

**PenTou（笔头）** 的取名灵感来自"好记性不如烂笔头"——把每一次有价值的 AI 对话固化为本地资产，让 AI 的产出真正可以**沉淀、回查、二次加工**。

PenTou 的核心设计原则只有一条：

> **数据归用户所有，以原生 Markdown 形式存储在本地文件系统中。**

没有专有数据库、没有云服务锁定、没有付费墙——你随时可以用 VSCode、Obsidian、Git 直接消费这些 `.md` 文件。

## 二、当前已实现的能力

### 1. 多源对话导入

PenTou 支持把不同平台、不同形态的 AI 对话归口到同一个本地仓库：

| 来源 | 输入形式 | 处理方式 |
| --- | --- | --- |
| ChatGPT 官方导出 | `conversations.json` | 沿 `mapping` 活跃分支递归还原消息流 |
| DeepSeek 导出 | `conversations.json` | 还原 REQUEST / RESPONSE / THINK；思考链自动转为 Markdown 引用块 |
| CLI 工具日志 | `.jsonl`（Claude CLI、Codex 等） | 逐行解析，识别 `type` / `role` 字段 |
| IDE / 脚本产物 | `.md`（含 frontmatter） | 严格按 `## User` / `## ChatGPT` 等角色边界切分 |
| 平台分享链接 | URL（DeepSeek 等） | 后端双轨抓取：API 嗅探优先，浏览器渲染降级，绕过 CORS 与基础反爬 |

**一次能拖入多个文件**，单个文件解析失败不会中断同批次的其他文件，UI 会精确告诉你哪条出了问题。

### 2. AI 对话自动采集

手动导入之外，PenTou 提供一条"发生即归档"的自动采集链路：

- **Ingest Gateway**：服务端统一上报入口（`POST /api/ingest`），token 鉴权；以 `(platform, externalId)` 幂等 upsert——同一段还在增长的对话反复重传也不会产生重复条目；内置密钥脱敏，agent 会话里的凭据不落盘。
- **CLI Collector**：监听 Claude CLI / Codex 等工具的本地会话日志，新对话自动上报，无需手动拖文件。
- **浏览器插件**：在网页端捕获 AI 对话原始数据，交由服务端统一解析入库——插件保持"哑采集器"，平台改版只需升级服务端。

### 3. 本地 Markdown 存储

每一条导入或生成的对话，最终都会落盘为：

```
data/conversations/<id>.md
```

文件结构是**人类可读**的 frontmatter + 消息正文：

```markdown
---
id: ...
title: ...
platform: ChatGPT
date: 2026-05-12T...
folderId: ...
---

## User
...

## AI
...
```

**Markdown 文件是唯一权威数据源**——检索索引只是可随时重建的只读派生物，应用重启全量扫描即可恢复状态。你可以把整个数据目录用 Git 管起来，跨设备同步、版本回溯都是现成的。

### 4. 全文与语义混合检索

搜索是与"对话 / 文档"同级的一等入口（命令面板式浮层）：

- **全文检索**：本地 SQLite FTS5 + BM25，跨对话与文档统一召回，带相关性排序与命中片段，点击结果直接跳转并高亮命中位置。
- **语义检索（可选）**：配置 OpenAI 兼容的 embedding 接口后，"我之前是不是和 AI 讨论过 X"这类模糊提问也能命中；关键词与语义双路召回经 RRF 融合排序。

一切索引都在本地生成与存储，零云端依赖。

### 5. 三栏沉浸式浏览

- **左侧栏 Sidebar**：对话/文档双 Tab 切换、文件夹树形组织（可拖拽分类、可批量选择）、关键词过滤、明暗主题与中英文一键切换。
- **中央内容区 MainContent**：与平台原生视觉接近的气泡渲染；代码块原生高亮、一键复制；Markdown 完整支持。
- **右侧导航 RightNav**：基于 User 提问自动生成"问题大纲"，点击即可滚动定位；长文本悬停展开完整内容。

### 6. 对话 → 文档：知识沉淀闭环

PenTou 不止是阅读器。它内置了一套**对话 → 文档 → 批注 → 重写**的加工闭环：

| 入口 | 行为 |
| --- | --- |
| **一键转文档** | 调用你配置的 LLM（BYOK，兼容 OpenAI 接口），把整段对话重写为结构化文档；P95 < 20 秒。 |
| **消息摘录** | 不依赖 LLM，直接把对话中的高价值片段按统一模板写入同源文档。 |
| **外部资料导入** | 走 **MinerU** 解析管线，PDF / Docx / PPTX 等高质量转 Markdown（含图片抽取落盘）；`.md` 与本地格式无需解析直接入库。 |

### 7. 阅读、批注、AI 重写

文档进入仓库后有两种工作模式：

- **阅读模式**：选中文字即可高亮、加评论。批注作为 sidecar JSON 持久化，刷新 100% 保留。
- **编辑模式**：所见即所得的 Markdown 编辑。

**关键能力是"批注驱动重写"**——你把若干条批注作为修订意见交给 LLM，PenTou 会生成一份新版本，原版本完整入历史。任何一次重写都能在版本面板里找回、对比、回滚。

### 8. AI 问答侧边栏

三栏布局右侧有一个**常驻的 AI 问答面板**：

- **上下文感知**：默认把当前选中的对话 / 文档作为问答上下文，无需复制粘贴；也可临时关闭上下文。
- **多会话持久化**：侧边栏对话独立保存到 `data/ai-chats/`，支持新建、历史切换与删除，不污染导入语料。
- **生成即沉淀**：问答结果可一键转为新文档，进入既有的批注 / 重写 / 版本 / 推送闭环。

### 9. 推送到 Obsidian

PenTou 不打算成为你的最终知识库——它擅长**采集与加工**，归档交给 Obsidian。一键推送通过 `obsidian://` URI 唤起目标 Vault；超长内容自动降级走剪贴板。

### 10. 安装与部署：从一条命令到私有服务器

**本机一键安装（推荐入门）**——装有 Node.js（≥ 20）的机器上，一条命令即可运行，无需 Git、无需构建：

```bash
npx -y @startist/pentou@latest
```

- 启动后自动打开浏览器进入 PenTou，端口被占用时自动换用相邻端口
- 数据落在启动目录下的 `pentou-data/`（目录即数据，可拷贝、可备份），同一目录再次启动即接续使用
- 本机模式默认免登录，且只绑定 `127.0.0.1`——局域网其他设备不可访问；想对外暴露必须显式指定 `--host` 并设置 `--password`
- 面向零编程基础用户，`docs/user-guide.md` 提供"让 AI Agent 代劳"的提示词与桌面一键脚本

**Docker 私有化部署**——面向 NAS / 云服务器的长期服务形态：

```bash
docker run -d \
  --name pentou \
  -p 127.0.0.1:7766:7766 \
  -e PENTOU_PASSWORD='your-strong-password' \
  -v /srv/pentou/data:/app/data \
  ghcr.io/<owner>/pentou:latest
```

```bash
docker run -d \
  --name pentou \
  -p 127.0.0.1:7766:7766 \
  -e PENTOU_PASSWORD='your-strong-password' \
  -v /srv/pentou/data:/app/data \
  ghcr.io/<owner>/pentou:latest
```

- 同时支持 `linux/amd64` 与 `linux/arm64`（兼容群晖、极空间等 NAS）
- 默认非 root（uid 1000）
- 数据卷与代码彻底解耦，升级 = `docker pull && docker compose up -d`
- TLS / 域名由你自己的反向代理（Caddy / Nginx / Traefik）承担

## 三、技术栈

PenTou 主张**轻量而完整**：

- **前端**：React + Vite + Tailwind CSS（v4），UI 组件遵循 shadcn 约定。
- **后端**：自研 Vite 插件（`pentouServerPlugin` / `documentsPlugin` / `mineruPlugin` / `obscura`）以 Express 风格中间件接管本地 I/O 与跨域抓取——开发态与生产态同构，并以预构建产物形式随 `@startist/pentou` npm 包分发。
- **渲染**：React Markdown + Framer Motion 微交互。
- **协作规范**：根目录 `CLAUDE.md` / `AGENTS.md` 声明 AI 协作准则（基于 Karpathy 编程规范），所有功能走 `spec.md → 评审 → 编码 → implementation-log.md` 的闭环。

## 四、谁会从 PenTou 受益

- **AI 重度用户**：每天产出大量对话，需要跨平台统一留存与回查。
- **非技术用户**：一条 `npx` 命令（或让 AI 代劳）即可在自己电脑上跑起来，无需服务器与部署知识。
- **知识工作者 / 内容创作者**：把对话当作素材池，提炼为文章、策划、笔记。
- **开发者**：归档技术方案、问题诊断、代码片段；可直接 Git 化管理。
- **数据隐私敏感者**：拒绝把对话上传到第三方云端，要求一切落在自己掌控的设备上。
- **Obsidian / Markdown 工作流用户**：希望 AI 对话能无缝并入既有知识库。

## 五、后续规划

### Roadmap A：跨库提问

检索（已落地的混合检索）与 AI 侧边栏（Phase 1 已落地）两条线的汇合点：对**全量历史**发起追问——比如"汇总我所有关于 RAG 的讨论"。检索负责"找回过去"，AI 侧边栏负责"基于过去生成未来"，让 PenTou 从被动的归档工具变成主动的思考伙伴。

### Roadmap B：分栏对比

同屏并排打开两段对话 / 文档进行对照阅读（已完成规划评审，待实施）。

### Roadmap C：一键迁移（R1 Code Complete）

PenTou 现在有三种实例形态：**本机一键安装**（`npx`，数据在本机目录）、**NAS Docker**、**云服务器 Docker**。安装门槛降到一条命令后，多实例并存成为常态，也带来了三类真实的搬家诉求：

- **试用转正**：先在本机 `npx` 跑起来试用，攒了一批对话与文档后，整体搬到 NAS / 云服务器的正式实例。
- **多端切换**：出门在外用云服务器 A，回到家用 NAS B，让 B 随时追上 A 的新增内容。
- **回迁本地**：注销云服务器时，把远端数据完整拉回本机，转为纯本地使用。

一键迁移将在界面上直接完成这些搬运：

- **端到端**：填写对端地址与密码 → 预览差异 → 执行，无需手动导出 / 导入或 scp 文件。
- **推送与拉取双方向**：本机实例只监听回环地址、外部不可达，因此迁移始终由能发起连接的一端主导——既能把本机数据**推送**到远端，也能从远端**拉取**回本机。
- **全量与增量**：一对话一文件的存储设计让内容差异比对天然成立；首次全量，之后只传变化部分，重复执行自动跳过已一致的内容。
- **本地优先、数据自持**：数据在用户自有的两个实例之间直连传输，不经第三方云端中转，与 PenTou 一贯的隐私取舍一致。

目标是让"在哪台机器上用"成为一个可随时切换的选择，而不是被某一个部署点绑定。

## 六、设计哲学

PenTou 不追求大而全。它在以下几个取舍上态度鲜明：

| 选择 | 不选择 | 原因 |
| --- | --- | --- |
| 本地 Markdown 文件 | 专有数据库 | 数据归属用户，工具链通用 |
| 一对话一文件 | 单一索引文件 | 易备份、易 diff、易迁移 |
| BYOK 自带 Key | 内置模型 / 付费墙 | 用户对成本与隐私完全可控 |
| 自研轻量后端 | 重型框架 | 单一仓库即可端到端运行 |
| Spec 驱动开发 | 直接动手写 | 每个功能可追溯、可评审 |

> **PenTou — 停止碎片化对话，开始构建属于你的 AI 知识资产。**
